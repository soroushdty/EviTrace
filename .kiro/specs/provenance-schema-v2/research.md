## Summary

- **Feature**: `provenance-schema-v2`
- **Discovery Scope**: Extension of an implemented subsystem (`provenance-core`) plus integration with a spec that is generated but not implemented (`extraction-contract-hardening`). Light discovery escalated to code-level verification of every claim in the brief; no external library, service or standard was needed, so no web research was done.
- **Key Findings**:
  - **Streaming and the pinned write contract are compatible.** A two-pass streaming writer (pass 1 encodes and digests every piece without touching the filesystem, pass 2 writes the temporary file and compares digests) produced byte-identical output on the realistic test graph (51,391 bytes) and on empty containers, and **all 363 tests of the serialization, end-to-end, run-provenance and orchestrator-provenance modules passed unchanged**, including every test that pins "encode before touching the filesystem" (M5). The brief's expectation that those tests are re-pointed is therefore met more strongly than required: they keep their meaning; new tests cover the mid-write failure that did not exist before.
  - **The hardening spec was amended while this spec was written** (M2): absence classes are `ids_cited`/`no_ids`, a new `absence_like` marker legitimises some claims without ids, `nr_origin` has a fourth value `human`, retention is triaged, `author_provenance` and `below_coverage` exist. This spec follows the amended names; the v2 brief's older wording (verified/unverified absence, `unverified_absence`, "no asserted claim without evidence") is superseded and listed as conflict C7.
  - **Removing the exhaustion-retain path breaks exactly 8 tests** (1 + 7, named in M3), as the investigation said; all are about reference-only exhaustion.
  - **The "never-marked required stage" rule would fail 41 existing tests** (29 in `test_provenance_completeness.py`, 8 in `test_provenance_end_to_end.py`, 2 in `test_extraction_pipeline_provenance.py`, 1 in `test_provenance_attribution.py`, 1 in `test_evidence_index_provenance.py`) and the **findings-degrade rule 3** (all in `test_provenance_end_to_end.py`; the union is 42), measured with crude prototypes of each rule alone (M4). Declaring the new stage before an emitter marks it would add more (50 failures with both rules, M4), so the declaration moved into the lineage task (D28). Process-level modules (`test_process_pdf_provenance`, `test_run_provenance`, `test_orchestrator_provenance`) already mark every stage and are unaffected.
  - **Model-visible lineage roughly doubles the artifact**: estimated +0.5 to +0.6 MB per document (+75 to +90%) at the default selection limits, dominated by `has_input` edges (M7). It is acceptable under the governing instruction, bounded in memory by streaming, and stated in the documentation.
  - **Recovery cannot live in `pipeline`**: `pipeline/__init__` imports the orchestrator, which loads configuration and the model client at import. The run-end sequence and the recovery entry point therefore move into the `provenance` package (`run_end.py`, `recovery.py`), and `pipeline.run_provenance` delegates to them (M9).
  - **Cross-invocation resume is dead today** (`RUN_FOLDER_NAME` is computed at import), so shards of a crashed run sit in a run folder no later process reuses, and orphan instance directories are only detected and reported at run start, and the explicit recovery command (guarded against live runs) is the only recovery (D31, M10).
  - **`tests/steering/test_spec_task_traceability.py` constrains `tasks.md`**: every `_Depends:_` id must be a task in the same file, so cross-spec prerequisites are written as prose bullets (M11).

### M5. Streaming writer prototype (measured)
- **Method**: scratch copy; replaced `_encode_artifact`/`write_graph` with a generator that yields the artifact piecewise (each node and each top-level value encoded with `json.dumps(indent=2)` and re-indented by two spaces per nesting level), a first pass that validates and digests, and a second pass that writes the temporary file and compares digests before `os.replace`.
- **Measured**: output equals `json.dumps(graph_to_dict(g), indent=2, ensure_ascii=False, allow_nan=False) + "\n"` byte for byte on the realistic test graph (51,391 bytes) and on empty lists/dicts; 363 passed (158 in the serialization module, the rest in the provenance end-to-end, run-provenance and orchestrator-provenance modules) with **no test modified**.
- **Why it works**: `json.dumps` escapes newlines inside strings, so re-indenting every line after the first of a nested dump cannot alter string content; empty containers print as `[]` and `{}`.
- **Implications**: Requirement 11 and design D19. Mid-write OS failure and digest mismatch are new failure modes with new tests. A randomised comparison against the complete encoding (property test) is a task, because the prototype covered one graph.

### M6. Document attribution and the recorder index (read)

### M7. Artifact growth of the evidence lineage (estimate from measured inputs)
- **Inputs (investigation, N=300)**: 0.67 MB per document; 114k nodes (380 per document) and 176k edges (587 per document); edges are 36.3% of bytes, so one edge costs about 243 KB / 587 = **415 bytes**; about 309 evidence nodes per document. Package sizes at the default caps on the three fixtures: 150, 102 and 141 items (mean 131). Default `num_chunks` is 5 (`configs/config.yaml`): four extraction calls and one synthesis call.
- **Calculation** (per document): selection step: 309 `has_input` + 131 `has_output` edges; five call steps: 5 x 131 = 655 `has_input` edges; total 1,095 new edges x 415 B = 455 KB. New id strings in `input_ids`/`output_ids`/`removed_ids` lists: 309 + 131 + 178 + 655 = 1,273 x about 95 B = 121 KB. Total about **+575 KB** (+86%). The old cited-only step inputs (about 120 edges) are a subset of the shown ids, so the net is about +520 to +575 KB: **about 1.2 MB per document**, about 1.2 GB at 1,000 documents and 2.5 GB at 2,000. Gzip compresses these id lists well (the investigation measured 22x on the artifact).
- **Implications**: Requirement 6.10 and the documentation task state the figure as an estimate. Streaming (D19) keeps the write bounded; `read_graph` of a very large artifact is a consumer concern (out of scope). Elision of structural edges was rejected by the owner and is not reopened.

### M8. Memory model (estimate and read)
- **Read/measured earlier (investigation)**: the end-of-run peak was the 4.3x `json.dumps(indent=2)` encoder transient; retained recorder store 0.39 MB per document; with accessors and a single-pass streaming writer the RSS delta at N=300 fell from 1,298 MB to 234 MB (0.78 MB per document).
- **Estimate**: v2 adds about 1,100 edge objects and 1,270 id references per document to the in-memory graph. Id tuples built from the recorded `EvidenceNode.node_id` string objects share storage (8 bytes per reference), so the recorder grows little; the graph's edge objects (about 500 B each) add roughly 0.55 MB, giving about **1.3 MB per document** in memory at run end (1.3 GB at 1,000 documents). The write itself adds a constant.
- **Implications**: The memory requirement is "the encoding transient does not grow with the number of documents" plus the shards guarantee, not "total memory is constant". Analysis (validation, completeness) still holds the whole graph; making it per-document was rejected (D23) because chain checks are cross-document and cost is irrelevant.

### M9. Where recovery and the run-end sequence can live (read and tested)
- **Read**: `pipeline/__init__.py` imports `orchestrator`, which at import calls `load_openai_config()`/`load_qc_config()` and imports the model telemetry; `python -m pdf_extractor.pdf_extractor` (CLAUDE.md) fails without `PYTHONPATH=src` in this environment (`ModuleNotFoundError`), while `PYTHONPATH=src python -c "import provenance"` works with no credentials.
- **Implications**: `provenance.recovery` can be run as `PYTHONPATH=src python -m provenance.recovery <instance_dir>` with no key. The run-end sequence (snapshot, build, carriers, validate, attach, mark, complete, write) is needed by both the normal run and recovery, so it becomes `provenance.run_end.finalize_run`, and `pipeline.run_provenance._finish` delegates. The pre-existing CLAUDE.md claim about `python -m pdf_extractor...` is inaccurate without `PYTHONPATH`; reported, not fixed here.

### M10. Resume reality and orphan instances (read)
- **Read**: `utils/path_utils.py` computes `RUN_FOLDER_NAME = run_<timestamp>` at import, and `pdf_processor.is_resumed` consults `OUTPUT_DIR` under that folder, so a second process never finds the previous output (investigation, reproduced there). `cost-and-run-reporting` plans to persist the output path.

## Architecture Pattern Evaluation

| Option | Description | Strengths | Risks / Limitations | Verdict |
|---|---|---|---|---|
| A. In-memory only, streaming write | Keep the recorder as the only store; stream the artifact at run end | Smallest change | A kill before run end still loses everything (the stated failure) | Rejected as the only mechanism; kept as the normal assembly path |
| B. Per-document shards plus in-memory assembly plus recovery | Each finished document is written once; the run end assembles from memory; a crashed run is assembled from shards | Durable at document granularity, deterministic, no new dependency | Disk duplication (shards ~ artifact size); recovery cannot restore run-wide marks | **Chosen** |
| C. Append-only JSON Lines log | One log appended per record | Finest durability | Torn last line, ordering across concurrent writers, replay cost; no per-document unit for resume pointers | Rejected |
| D. Embedded database (SQLite) | Records in tables | Queryable, transactional | New binary store, harder byte-determinism and audit hashing, privacy review | Rejected |
| E. Rebuild provenance from extraction outputs and caches after a crash | Re-derive records | No duplicate storage | Not provenance: model-visible evidence, stage marks and findings are not in the outputs | Rejected |

| Option (lineage representation) | Description | Verdict |
|---|---|---|
| L1. Steps with evidence inputs and removed ids (brief decision 5) | Selection step plus per-call steps whose inputs are the shown nodes | **Chosen** |
| L2. New node kind "evidence set" referenced by steps | One node per distinct package | Rejected: a vocabulary addition beyond the brief, and consumers would need a second lookup |
| L3. Cited-only inputs (v1) | Unchanged | Rejected: loses what the model could see (investigation W3) |

## Design Decisions

### D1. Schema release shape
- **Context**: Decision 1-2 of the brief.
- **Alternatives**: (a) 1.1.0 with new keys: an old reader drops unknown top-level keys with one warning and loses them on rewrite (the failure being avoided); (b) 2.0.0 with a converter from 1.x: no consumer of 1.0.0 exists, so a converter is untested code that implies a promise; (c) **2.0.0, major 2 only**.
- **Selected**: (c). Top-level order `schema_id, schema_version, run, extensions, stages, resumed_documents, nodes, edges, missing_segments, validation, completeness`. `SUPPORTED_SCHEMA_MAJORS` stays derived from the writer's major, so it becomes `(2,)`. A 1.0.0 fixture written by the previous writer is captured **before** any change (task 1.1) and asserted to be refused.
- **Rationale**: Honest versioning; the artifact is small enough that "explicit" beats "compatible".
- **Compatibility rule (restated)**: from 2.0.0 on a top-level key may be added in a minor release because older 2.x readers preserve unknown top-level keys under `extensions["x-compat-unknown"]` (read-then-write keeps the content, relocated); a vocabulary addition or removal, a key rename/removal or a semantic change is a major release.

### D2. Stage status object
- **Selected**: `stages = {order, contracts, run, documents}`; `run` has an entry for every declared stage; `documents` has an entry for each processed document and, inside it, for every stage that was marked (an unmarked stage is absent, which is what `not_run` means for a document). Each entry is `{status, reasons[]}`. Status precedence `not_run < skipped < complete < failed`; a skip never replaces complete or failed. Run-wide failure reasons now keep every distinct reason (v1 kept the first only) so run and document scopes behave alike.
- **Alternatives**: store only failures (rejected: `skipped`/`complete` are needed to interpret a document); store `not_run` explicitly for documents (rejected: more bytes with no information); flatten reasons into one string (rejected: the investigation found this made multi-valued reasons unrecoverable).

### D3. Never-marked rule and "upstream"
- **Selected** (amended by D36): for a document D and a required stage S (contract scope `document` or `claim`) with effective status `not_run`: if no stage of D is `failed` and every stage T with `stage_sort_key(T) < stage_sort_key(S)` (never `STAGE_ORDER.index`, D37) and scope `document` or `claim` has effective status `complete` or `skipped`, then D is `undetermined` with reason `stage 'S' was never marked`. For a run-scoped S (only `chain_validation`): never marked while the run has processed documents makes the run `undetermined`.
- **Skipped counts as satisfied** (a judgement call beyond the brief's wording "upstream stages are complete"): an intentional skip is an accounted-for stage, and leaving the next stage unmarked after a skip is as much a forgotten mark as after a completion. A failed, not-run or unmarked upstream explains a downstream gap and adds none.
- **Alternatives**: "any unmarked stage degrades" (rejected: after a failure it multiplies noise); "complete only" upstream (rejected: an all-prefilled document would need no marks for later stages, hiding a forgotten mark); a per-stage "may be skipped" flag in the contract table (rejected: complexity with no benefit; the pipeline marks skips explicitly).

### D4. Findings and completeness
- **Selected**: effective severity (after `severity_overrides`) decides: critical and error findings degrade; warning and info never do. Attribution (first rule that applies): (1) the claim named by `node_id`; (2) the documents of the node named by `node_id` (evidence, source, claim: `document_of`; derivation step: every `step_documents`); (3) the document named by `details["source_id"]`; (4) the document of the `from_id` of the edge named by `edge_id`; (5) the run. A finding contributes `incomplete` with reason `finding:<code>`. Table of the shipped codes in design.
- **Why effective severity and not a fixed code list**: the report and completeness must agree by construction; overrides are the operator's explicit policy and the artifact records them. Support-derived gaps (`unsupported`, `missing_anchor`, `missing_records`) remain graph-derived and are **not** removable by an override, so an uncited assertion cannot be made complete by downgrading a finding.
- **`fail_run_on_severity`**: unchanged; it logs an ERROR and sets the run-summary flag from the same effective findings; neither feature reads the other's output.
- **Alternatives**: degrade on any finding (rejected: `missing_anchor`/`orphan_node` noise); degrade only on code list (rejected: drifts from the report); degrade at run level only (rejected: hides which document).

### D5. Typed absence (amended after the hardening review)
- **Selected**: `ClaimNode.answer ∈ {asserted, not_reported, absence_like}` and `ClaimNode.absence ∈ {not_applicable, ids_cited, no_ids}` (the same words as hardening's report classes). `answer` follows the persisted marks: a field with `nr_origin` is `not_reported`; a field with `absence_like: true` is `absence_like`; every other field is `asserted`. `ids_cited` iff at least one cited id resolves to an evidence node of the run (anchors are irrelevant to an absence: the ids record where the author looked); a pipeline-, prefill- or human-origin not-reported claim cites nothing and is `no_ids`. For a not-reported or absence-like claim `support` is `not_applicable` when it cites no evidence node and the computed anchor-rule value (`supported` or `missing_anchor`) when it does (D27); completeness never turns either into a gap. Counts: `claims, asserted, supported, missing_anchor, unsupported, absence_like, ids_cited, no_ids, pipeline_produced, human` over final claims (claims not targeted by a `revises` edge); `ids_cited` and `no_ids` count model-origin not-reported claims only, `pipeline_produced` counts origins `prefill` and `pipeline` (renamed from `pipeline` because it also holds prefill, D37), `human` counts origin `human`, and `absence_like` counts absence-like claims whatever their origin and ids. `asserted = supported + missing_anchor + unsupported`; `claims = asserted + absence_like + ids_cited + no_ids + pipeline_produced + human`.
- **Finding**: `absence_without_ids` (info, overridable) for a model-origin not-reported claim in state `no_ids`. No finding for `absence_like` (the contract exempts it), prefill, pipeline or human origin.
- **Alternatives**: a fourth `ClaimSupport` member - first rejected here as mixing axes, then **adopted** as `not_applicable` after the review (D27); deciding from the text `nr` or from the extraction map (rejected: provenance would re-interpret the contract; the marker is persisted exactly so that no consumer loads the map); treating `absence_like` as asserted (rejected: it would read `unsupported` when the model legitimately cites nothing, the exact W1 failure for category values); folding `absence_like` into `no_ids` (rejected: hardening keeps them distinct classes, and `evaluation-harness` needs asserted-only denominators that exclude both).
- **Honest wording**: v2 never calls an absence "verified"; `ids_cited` is documented as "ids shown and cited". A model-origin `nr` whose cited ids all pass hardening validation but resolve to no recorded node (a skipped invalid evidence item or a stale cache) is `no_ids` in provenance and `ids_cited` in hardening's report column; the two agree on every output where evidence emission succeeded (conflict C2).
- **Superseded sentence**: the brief states that after both specs an accepted output contains no asserted claim without evidence; `absence_like` claims may legitimately carry no ids, and `unsupported` now arises for asserted claims only from non-model origins, adapter-dropped ids and corrupt caches.

### D6. Claim origin vocabulary
- **Selected**: `ClaimOrigin = model | prefill | pipeline | human | import`; mapping `model`→`model`, `pipeline_prefill`→`prefill`, `pipeline_empty_value`→`pipeline`, `human`→`human`. `pipeline` means: a value the pipeline itself produced without a model call that is not metadata prefill. An unknown origin mark, or a field carrying both marks, is treated as asserted with the caller's origin and a warning (fail toward asking for evidence).
- **Alternatives**: map `pipeline_empty_value` to `import` (rejected: wrong meaning); to `prefill` (rejected: merges two fallbacks that hardening deliberately separates).

### D7. Exhaustion fails the document
- **Selected**: remove the block entirely (including hardening's triage); keep `_report_references` for accepted outputs (duplicates). Stage failure reasons come from two sources: `RepairRetryLoop.exhaustions` (new read-only mapping, key `(call_kind, chunk)`, value the `RepairExhaustedError` metadata plus `codes`, the validator's closed code set) for exhausted calls, and the manifest `failures` list for any other failure. Extraction reason: one entry per failed chunk `chunk N: <error_type> [codes: a, b]: <last_error>`; synthesis reason: `synthesis chunk N: <error_type> [codes: ...]: <last_error>` from `exc.metadata["last_error"]`; other exceptions `type: message`. Limit 4,000 characters with an explicit omitted-characters marker (the validator reports at most 20 violations; 4,000 holds a full message of ordinary length).
- **Alternatives**: keep retention behind a flag (rejected: provenance would still change extraction when on, and a switch whose off position is the defect gets used); parse codes out of the message (rejected: brittle); read only the manifest (rejected: it lacks codes and, for several failed chunks, `error` names only the last).

### D8. Evidence lineage
- **Selected**: new declared stage `evidence_selection` (contract: `derivation`, scope `document`) placed right after `evidence_index` in `STAGE_ORDER`; steps use the existing derivation kind `filter` (no vocabulary change); selection step `inputs` = the document's evidence nodes (header metadata nodes excluded), `outputs` = the package nodes, `removed_ids` = the rest, `removal_reason` begins `selection_cap:` and names `max_items` and `max_chars`; mitigation step per call with withheld ids: reason begins `token_budget:`; extraction/synthesis steps' inputs = the call's shown nodes (synthesis keeps the contributing claim ids), extension `x-pipeline-package_sha256` and the existing `x-pipeline-chunk`. Finding `cited_evidence_not_shown` (error) when a claim cites an evidence node outside the evidence inputs of its producing `extract`/`synthesize` step (vacuous when the step has no evidence inputs, as for direct callers). The lineage is emitted at every exit after the first model call, so a failed document still shows what the model saw. Filter steps keep their outputs inside their inputs, so the existing in-place rules keep evidence attributed to `evidence_index` and keep cycle detection quiet.
- **Alternatives**: a new `select` derivation kind (rejected: a vocabulary change with no new meaning); one selection step per call (rejected: the paper-level package is shared; per-call steps are only for withheld ids); recording withheld ids without a reason (rejected: Requirement 6.1 of provenance-core).

### D9. Run-instance identity
- **Selected**: `inst:<sha256[:16]>` over `[run_id, sorted processed document fingerprints, created_at]` using the existing canonical digest helper; instance directory name `inst-<16 hex>`.
- **Alternatives**: random nonce or process id (rejected: not derivable, breaks byte-determinism of header/shards for equal inputs); sequence number (rejected: needs shared state). Two executions in the same second over the same documents collide; the no-overwrite guard (D14) then sees the same instance and treats it as the same run (an identical-input rewrite), which is the correct reading.

### D10. Fingerprint scope
- **Selected**: the `extraction` section of `identity_config` gains `sanitize_extracted_values`, `exported_value_normalizer` and `extraction_contract` (= `EXTRACTION_CONTRACT_VERSION`). `agent_schema.json` and `final_output_schema.json` stay out (the contract version stands for the prompt and the output contract; a prompt edit without a version bump is invisible, recorded as a risk).
- **Why the contract version**: `run_id` excludes `agent_schema.json`, so a prompt/contract change would otherwise leave `run_id` unchanged while the meaning of a not-reported answer changes; the version is the declared proxy.
- **Alternatives**: hash `agent_schema.json` directly (rejected: couples the fingerprint to a file the hardening spec rewrites; the version is the owner-controlled signal).

### D11. Instance directory and the no-overwrite guard
- **Selected**: artifact path `<run folder>/<output_subdir>/<inst-...>/provenance_graph.json`, shards under `<inst>/shards/<document fingerprint>.json`, header `<inst>/run.json`. `write_graph` refuses to replace an existing artifact whose `run_instance_id` differs (bounded prefix scan of the existing file; an unreadable or foreign file counts as different) and raises `ArtifactConflictError` (a `FileExistsError`); the pipeline degrades with a warning naming both files.
- **Alternatives**: a fixed `provenance_graph.json` with the previous one renamed (rejected: moving files is itself a hidden mutation; consumers would race); timestamp suffix in the file name (rejected: no stable directory for shards and recovery); keep v1 layout and only warn (rejected: still overwrites).

### D12. Resumed, unrecorded and empty runs
- **Selected**: `resumed_documents` entries `{document_key, source_id, output_path, extraction_contract, reason, earlier_artifact, earlier_shard}` with `ArtifactReference {path, sha256, run_instance_id}`; the pointer is found by scanning sibling instance directories for `shards/<fingerprint>.json`, newest `created_at` first; paths are POSIX, relative to the new instance directory. Documents left out for other reasons are listed in `extensions["x-pipeline-unrecorded_documents"]`. A run with no processed document builds its run identity from the corpus identities (the run-wide fingerprints do not depend on a PDF) and writes an artifact with no nodes whose completeness reason states why.
- **Alternatives**: one generalised list with a `status` field (rejected: the brief names `resumed_documents`, and mixing "already done elsewhere" with "never recorded" would blur the one thing an auditor must tell apart); listing the resumed documents inside `document_fingerprints` (rejected: completeness enumerates documents from it, measured in the investigation).

### D13. Shards
- **Selected**: one JSON file per document, `evitrace/provenance-shard` 1.0.0, same encoding discipline as the artifact; content `{schema_id, schema_version, run_id, run_instance_id, source_id, nodes, edges, findings, stages}` where `nodes`/`edges`/`findings` are the records the recorder holds for the document (explicit edges only; structural edges are derived at assembly) and `stages` the document's marks with reasons; no clock, no run-level data. Written atomically (temporary file in the same directory, flush, `fsync`, `os.replace`) when the document finishes. The run header `run.json` (`evitrace/provenance-run-header` 1.0.0) is written before the first document. Never deleted by the pipeline; an instance directory is removable as a unit.
- **Alternatives**: store derived structural edges in shards (rejected: duplicates information and invites divergence); write shards at run end (rejected: that is the failure window); delete shards after a successful artifact (rejected: later runs point at them; durable evidence should not be silently removed).

### D14. Recorder accessors and the per-document index
- **Selected**: public `run`, `get_node`, `has_source`, `document_stage_status`, `document_records`, `mark_stage_skipped`, and constructor context (`extensions`, `resumed_documents`). The index is filled at record time with the shape rule from `identity.source_scope_of`; a finding is attributed by its node, by `details["source_id"]`, or by the `from_id` of its edge.
- **Alternatives**: slice a full snapshot per document (rejected: quadratic again); a per-document recorder facade that tags records (rejected: every future emitter, such as `evidence-routing`, would have to use it or its records would silently miss the shard).

### D15. Run-end sequence moves into the provenance package
- **Selected**: `provenance.run_end.finalize_run(recorder, directory, severity_overrides, stage_contracts_strict, carrier_source, ...)` owns snapshot, build, carriers, validate, attach, mark, post-validation snapshot, attach stages, completeness, attach, write; `pipeline.run_provenance` keeps settings, the summary, the fail-run severity and delegates. `provenance.recovery` rebuilds a recorder from shards by replaying records through the public `record_*`/`mark_stage_*` methods and calls the same function, which is what makes normal and recovered artifacts equal by construction.
- **Alternatives**: duplicate the sequence in a recovery module (rejected: two sequences drift); put recovery in `pipeline` (rejected: import weight, M9).

### D16. Recovery
- **Selected**: `recover_instance(instance_dir, carrier_source=None, force=False, replace=False)`; CLI `PYTHONPATH=src python -m provenance.recovery <instance_dir> [--force] [--replace] [--carrier-source module:callable]`; exit 0 on success, 1 on failure with a message; refuses when `provenance_graph.json` exists unless `--replace`, and refuses a live-looking instance unless `--force` (D31). Policy (severity overrides, strictness) comes from the header's extensions. The recovered artifact adds `extensions["x-provenance-recovery"] = {recovered_from, shards_used, documents_without_shard}`. Orphan siblings are only detected and logged at run start (D31; the first draft recovered them best-effort).
- **Cannot be restored**: run-wide stage marks, findings that name no document, carriers attached at run end (re-applied when a carrier source is given). Documented.

### D17. Privacy attach path
- **Selected**: `graph.attach_carriers(graph, carriers)`; `CarrierConflictError(ValueError)`; decision identifier in `PrivacyCarrier` (`decision_id`, string, requires `decision`, stored verbatim); `carrier_source(graph, phase)` where phase is `"pre_validation"` or `"post_validation"`; structurally rejected carriers attach before validation and are refused after.
- **Alternatives**: an adapter parameter (rejected: nodes are created in several places and decisions arrive after evidence nodes are recorded); a pre-record hook (rejected: the validation record never passes through the recorder; privacy decisions arrive later); post-hoc enrichment of the written artifact (rejected: invalidates digests that audit export takes, and cannot recompute completeness).

### D18. Differential test
- **Selected**: run the real orchestrator path (`build_qc_bundle`, evidence index, validator, repair loop, `process_pdf`, manifest; only the model call, GROBID and tokenizer stubbed, as in `test_provenance_end_to_end.py` of the pipeline tests) twice over the same scripted responses, provenance on and off, over a set of response scripts (all valid; not-reported with and without ids; an unknown id that exhausts repair; a parse error that exhausts repair; a synthesis exhaustion) and compare the extracted JSON (path-normalised), `manifest.json`, evidence cache bytes and the full `extract_chunk` argument lists. A Hypothesis variant draws scripts from a small grammar.

### D19. Streaming writer contract
- **Selected**: two-pass. Pass 1 iterates the piece generator, discarding text, counting bytes and hashing; any content error raises before the filesystem is touched (the old guarantee, verbatim). Pass 2 writes the temporary file in the same directory, flushes and `fsync`s, compares the digest to pass 1 and `os.replace`s. Any exception after the directory exists removes the temporary file and leaves the previous artifact.
- **Alternatives**: single pass with cleanup on any error (rejected: loses the "no directory created on a content error" guarantee and requires re-pointing five tests for no gain); write to an in-memory buffer first (rejected: that is the problem).

### D20. Memory statement
- See M8. The requirement is the independence of the encoding transient from document count, plus durability. Per-document analysis was rejected (D23 below).

### D21. Guards and tests
- The stage-contract drift guard gains `mark_stage_skipped` in `_STAGE_SINKS`, `evidence_selection` in `_CORE_STAGES` and the probe; the 7.1 import-isolation guard's allow-list loses the now-stale `graph._scope_of` partition entry and gains a justified `identity.source_scope_of` entry (the `#` separator), the new modules are scanned automatically, and the stream digest's finisher is named `finish()` so the hash-call pattern stays confined to `identity.py`; the 9.4 label-interpretation scan covers `attach_carriers` and the new `decision_id` key; the 7.2 property tests gain strategies for the new records; the 7.3 prefix goldens are untouched (v2 never touches prompts); the 7.4 end-to-end test is extended.

### D22. Counts and completeness attachment of absences
- Covered in D5; the invariants (`claims = asserted + absence_like + ids_cited + no_ids + pipeline + human` and `asserted = supported + missing_anchor + unsupported`) are asserted by a property test.

### D23. Per-document analysis rejected
- **Context**: bound memory by validating and completing one document at a time from shards.
- **Rejected**: chain checks are cross-document (`duplicate_identity`, `evidence_out_of_run_context` with `foreign_source`, `source_not_represented`), run-level contract diffs need all documents, and per-document analysis would change finding codes for cross-document problems. Cost is irrelevant; correctness is not.

### D24. Coverage context
- **Selected**: the hardening report marks rows of a document `below_coverage` from the manifest `evidence_coverage.below_threshold`. Provenance cannot import the pipeline, so the pipeline passes the flag in: `RunProvenance.finish_document` reads the document's manifest entry and stores `below_coverage` (true, false or null when unknown) in the shard; `finalize_run` passes the per-document flags to `compute_completeness`, which puts `below_coverage` on each document's `ClaimCounts` and, on the run's counts, `true` when any processed document is below coverage, `false` when all known flags are false, `null` otherwise. Storing the flag in the shard keeps recovered artifacts equal to normal ones.
- **Alternatives**: persist coverage per claim (rejected: duplicates a manifest fact 62 times, the reason hardening gave); derive it in provenance from the selection step (rejected: the ratio is the pipeline's own measure of substantive text, not computable from node ids).

### D25. Header citations use the single header-sourcing rule
- **Selected**: `claim_provenance.header_citations` cites `M-first-author`/`M-publication-date` only when `evidence_index.prefill_source(bundle, field)` is `tei_header` and the current TEI header value equals the prefilled value. Because hardening's equivalence test requires every cited value to be header-sourced, the edit only removes the second independent rule; behaviour on the three fixtures and on stale caches is unchanged. Depends on hardening 5.2.

### D26. Every task is committable green; ownership of changed tests
- **Context**: the independent review found tasks that would leave the suite red (the new stage declared before its emitter; version fixture; the artifact path; patched names after the run-end sequence moved).
- **Selected**: each flipping task owns and re-points, in the same commit, the existing tests it breaks; the design carries a table task by task (Existing tests that change, by owning task). `build_graph` fills `stages` only after the serializer writes it (so `graph_from_dict(graph_to_dict(g)) == g` holds between tasks); test fixtures mark stages through a helper that iterates `STAGE_ORDER`.
- **Rejected**: red intermediate commits (breaks one-tick-per-commit); marking tests `skip` (hides regressions).

### D27. `ClaimSupport.not_applicable` (supersedes the earlier "no fourth support member")
- **Context**: with `unsupported` stored for absence answers that cite nothing, a consumer that ignores `answer` would re-read the W1 mislabel (a legitimate "not reported" as an unsupported assertion).
- **Selected**: since 2.0.0 is a major release, `ClaimSupport` gains `not_applicable`: given to a not-reported or absence-like claim with no cited evidence node; an absence answer with cited evidence nodes keeps the computed value (`supported`/`missing_anchor`); `unsupported` is reserved for asserted claims. Findings and counts are unchanged: the unsupported-claim findings already test `answer`, and counts classify by answer first, so no claim is counted twice (asserted buckets use only asserted claims).
- **Rejected**: keeping `unsupported` "for compatibility" (the compatibility is with a release nobody consumed); a separate boolean (two fields for one axis).

### D28. The evidence-selection stage is declared with its emitter
- **Context**: declared in an early foundation task, the never-marked rule (task 5.2) would flag every document for a stage no emitter marks until the lineage task; measured 50 failures (M4).
- **Selected**: declare the stage, update the drift guard core-stage list and the contract tests in the lineage task (8.4), the task that makes `process_pdf` mark it. Group 2 therefore has three tasks. Earlier fixtures iterate `STAGE_ORDER`, so the late declaration breaks only the few tests that spell stage lists (owned by 8.4).
- **Rejected**: declaring early with the rule off (two states of one rule to test); marking the stage in all emitters first (the emitter needs the declared stage to record a derivation step).

### D29. Fixture sequencing and the shared run identity
- **Selected**: task 1.1 asserts the 1.0.0 fixture by raw JSON (no reader) and adds the refusal test as `xfail(strict=True, reason="task 6.2")`, so task 2.3 (`run_instance_id` required) cannot break it and 6.2 un-xfails it. In 2.3 `_small_graph()`'s literal run identity and the realistic recorder's derived one are given the same literal `run_instance_id` so the no-overwrite guard (6.4) sees one instance; without it `test_a_failing_replace_leaves_no_temp_file_and_keeps_the_previous_artifact` would fail with `ArtifactConflictError` instead of the expected `OSError` (follows from the design: the two graphs have different run ids; reproduced by the reviewer, not by me, because my scratch copy has no guard).
- **Rejected**: moving the version guard before 2.3 (a half-implemented reader in the middle of the vocabulary task).

### D30. `skipped` only where the pipeline positively knows
- **Selected**: `DocumentClaims.mark_skipped(stage, reason)` is called by `process_pdf` at four known conditions (no model field; no prefilled field; no extraction chunk with fields; the existing branch that skips synthesis). A stage that is merely unmarked is never converted: a silently returning emitter stays detectable by the never-marked rule.
- **Rejected**: a bulk `mark_unrun_skipped` (my first draft): it would have hidden exactly the defect the rule exists to find.

### D31. Orphan instances: detect and report, recover only by explicit command
- **Selected**: at run start only detect (header present, artifact absent) and log the command `PYTHONPATH=src python -m provenance.recovery <instance_dir>`. The command refuses an instance whose `run.json` or shards were modified within `LIVENESS_THRESHOLD_SECONDS` (1800, documented) unless `--force`, and refuses to overwrite an existing artifact unless `--replace` (same run instance only). `provenance/__init__` does not import `recovery` (running `python -m provenance.recovery` with the package importing it raises a `RuntimeWarning` from `runpy`; reproduced in the scratchpad with a toy package). Documentation states that recovery needs the same memory as a normal assembly and does not solve out-of-memory in the analysis at very large corpora. Pointers of resumed documents are discovered at run start from whatever exists (an orphan contributes `earlier_shard`, `earlier_artifact: null`); a later recovery does not rewrite them.
- **Rejected**: in-process automatic recovery (races a live run in the same directory; a recovery that exhausts memory would take down the new run); lock files (stale locks after a crash are the problem being solved); a shorter liveness threshold (a rate-limited document can take many minutes without writing a shard).

### D32. Identical-content PDFs and shards
- **Selected**: `finish_document` holds a per-fingerprint lock around reading the coverage flag, `document_records` and `write_shard`, so an older snapshot cannot replace a newer one; `shard_filename` accepts only `[A-Za-z0-9]{1,128}` because the identity shape check forbids only `#` and whitespace (a `/` or `..` would escape the shard directory); per-source stage status is shared (one document's failure marks both), which is documented and tested; the case is already an error through `duplicate_identity`.
- **Rejected**: one shard per document name (breaks the source-id keyed pointers and double-counts the shared document).

### D33. Compatibility rule gaps
- **Selected**: the writer always stamps `PROVENANCE_SCHEMA_VERSION` (a graph read with a newer minor and unknown keys relocated into the extensions would otherwise claim a version it does not implement); adding a key to a record without a free-form slot (`run`, `stages`, `ClaimCounts`, completeness entries, segments, report containers) is a major change and the decoder's warning says so; run-level extension keys are validated against the namespaced pattern, with non-conforming keys relocated under the compatibility key like node-level ones.
- **Rejected**: carrying the read version over (breaks the rule it states); validating by rejecting the artifact (a reader must not refuse data it can preserve).

### D34. Explicit `not_run`, completeness scope, empty selection
- **Selected**: `stages.documents` writes `not_run` explicitly for every declared stage of every processed document (about 450 bytes per document); the run completeness entry carries `scope` (`full` | `partial`, partial when resumed or unrecorded documents exist) because a run entry that reads `complete` can otherwise be mistaken for a complete corpus; no separate high-absence indicator (the counts carry it); a document with no evidence items but a model call marks `evidence_selection` failed instead of recording an empty step that would trip `inconsistent_derivation`.
- **Rejected**: a report-level scope field (the review asked for the run entry); omitting `not_run` entries (derived rather than explicit).

### D35. The `not_shown` reason in hardening's validator stays
- **Selected**: once retention is removed the sink-mode reason `not_shown` is reached only by direct callers of the validator; v2 keeps it deliberately (documented API of a hardening-owned leaf with its own tests; `multiagent-extraction` may reuse the sink mode) and task 8.2 only rewrites the docstring to say who reaches it.
- **Rejected**: deleting it (cross-spec churn and test changes for no behavioural gain).

### D36. Lineage on every exit, and the never-marked interaction
- **Selected**: `process_pdf` calls `emit_evidence_lineage` from a `finally` covering everything from the first model call to the end, so extraction failure, synthesis failure, `not write_ok`, a raised write error and any unexpected exception are covered; tests per exit. The never-marked rule is suppressed for a document with any failed stage (a failure can legitimately end emission early and the document is already undetermined with the reasons), and applies when upstream stages are complete or skipped and nothing failed; the orchestrator's exception handler marks `evidence_selection` failed together with the claim stages that are still `not_run`.
- **Rejected**: suppressing only when an upstream stage failed (it would report a lineage stage unmarked merely because a later write failed); marking the stage failed on every error path by hand (many sites).

### D37. Smaller items
- `StreamDigest.finish()` (not `hexdigest`) keeps the hashing guard single-module. Completeness uses `graph.stage_sort_key`, never `STAGE_ORDER.index` (the attribution guard). `ALLOWED_SEPARATOR_USES`: the `graph._scope_of` entry goes stale when it delegates to `identity.source_scope_of`; a justified entry is added for identity. `RecordedRun.stage_failure_reasons` becomes a tuple: `graph._failed_stage_segments` (calls `.strip()`; a tuple would silently read as "no reason recorded") and `completeness._normalize_status`/`failed_stages` (keep only `str`; tuples would be silently dropped) are edited with the recorder task. `ClaimCounts.pipeline` is renamed `pipeline_produced` because it also counts prefill-origin not-reported claims; hardening's report class stays `pipeline`. Documentation tasks are added for the root `README.md` module table and for docstrings/comments that describe retention (`process_pdf`, `RepairRetryLoop`, `claim_provenance`, the validator sink mode).

## Risks & Mitigations

- **Artifact doubles in size (about +0.5 to +0.6 MB per document)** — streaming bounds the write; sizes documented; gzip recommended for transport; elision rejected by the owner.
- **In-memory graph at run end is about 1.3 MB per document (estimate)** — shards guarantee nothing is lost if the run-end step is killed; the recovery command re-runs assembly alone in a fresh process; revisit with a measured run.
- **Shards plus resume semantics** — a same-content PDF pair writes the same shard twice and the last write wins with the recorder's first-record-wins content; a resumed document's pointer is only as good as the sibling instance directories that survive (null with a stated reason otherwise); cross-invocation resume is out of scope and dormant.
- **Streaming write contract** — the two-pass digest comparison turns nondeterminism into a failed write instead of a wrong artifact; a randomised equality test against the complete encoding guards the re-indent method.
- **41 + 3 existing completeness tests change** — measured (M4); they are fixture changes (stages marked), owned by tasks 5.2/5.3 and listed in the design's ownership table.
- **Prompt change in hardening is not mine, but lineage relies on `package_sha256`** — if hardening renames the field the task fails at its first test; the published names are listed in the design.
- **Hardening is not implemented yet** — every v2 task that touches `process_pdf` states its hardening prerequisite; all interface names are taken from the hardening design and are Assumption A10.

## Assumptions not verified

- **A1** The artifact growth figure is a calculation from measured composition, not a measured run (M7).
- **A2** The in-memory growth (about 1.3 MB per document) is an estimate (M8).
- **A3** Orphan instance directories only appear in a reused run folder after `cost-and-run-reporting` makes resume work; detection and the recovery command are tested on constructed directories. The 30-minute liveness threshold is a judgement (A14).
- **A4** Sixteen hexadecimal characters are enough for a run-instance id within one run folder; a collision is treated as the same run by the guard.
- **A5** Existing serialization fixtures share one `run_instance_id` once it is added, so the no-overwrite guard does not trip them; if not, fixtures are adjusted.
- **A6** `fsync` per shard is affordable at a couple of thousand documents (not measured).
- **A7** No real model output exists; absence rates are unknown and no test asserts any.
- **A8** The recorder's shape-based attribution agrees with `graph.document_of` for every well-formed record (an agreement test is planned; malformed records are out of its domain).
- **A9** The disk space for shards (about the artifact size again) is available on the run volume.
- **A10** The hardening interfaces exist as in the amended design (`ShownEvidence` fields, `RepairRetryLoop.shown_evidence`, `nr_origin` with four values, `absence_like`, `prefill_source`, `EvidenceBundle.author_provenance`, `EXTRACTION_CONTRACT_VERSION` in `pipeline/validator.py`, the report class names); hardening is generated and amended but not implemented.
