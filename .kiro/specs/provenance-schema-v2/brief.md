# Brief: provenance-schema-v2

## Problem
`provenance-core` shipped (schema `evitrace/provenance-graph` 1.0.0, validated GO 2026-10-11), but the post-validation review (`investigation-2026-10-12.md`, items W1–W9) showed that the artifact and its completeness semantics are not yet scientifically credible enough for audit use:
- A model's explicit "not reported" answer is classified like an unsupported assertion, so document and run completeness are constant `incomplete` for any realistic `nr` rate (1% `nr` → 18/40 documents complete; ≥5% → 0/40).
- Completeness is blind to findings (a critical `graph_cycle`, a retained `dangling_reference`, `duplicate_identity` leave documents `complete`) and to stages that never ran (`not_run` is never "missing"); stage status is not serialized, so the artifact is not interpretable without the pipeline (Req 7.3) and audit-export cannot derive `stage_failures`.
- With provenance on, repair exhaustion on reference-only problems retains the output (provenance changes extraction); a retained document reads `complete` with a critical finding.
- A resumed or empty run leaves no trace of the documents it did not process, an artifact can silently overwrite an earlier one with the same `run_id`, and `run_id` identifies a configuration, not an execution.
- Provenance can be lost entirely: the end-of-run serialization peak (≈4.3 MB/document RSS, `indent=2` pure-Python encoder) can OOM-kill the process at ≥~1000 documents after all extraction has finished; reruns then treat the documents as resumed and never regenerate provenance. Per-document `recorder.snapshot()` calls are quadratic.
- Privacy-core has no designed path to put a carrier on a node (the ValidationRecord is created inside `attach_validation`, decisions arrive after evidence nodes are recorded, the carrier cannot be tied to the audit record).
- The model-visible evidence is not recorded: step inputs are the cited ids only; selection/pruning leaves no trace (Req 6.1/6.7 partial).

## Governing instruction (from the owner)
**Cost and time of work are not a concern; accuracy and scientific credibility supersede them.** Prefer explicit over derived, durable over fast, honest versioning over compatibility shims.

## Decisions already made with the owner (do not reopen; requirements/design record rationale)
1. **One deliberate schema release, `PROVENANCE_SCHEMA_VERSION = "2.0.0"`**, batching every schema change below. 1.0.0 is treated as never released (nothing consumed it). The reader supports major 2 only and refuses 1.x with `UnrecognizedSchemaVersionError` naming found/supported versions (an old reader silently dropped unknown top-level keys and lost them on rewrite — that is the failure mode being avoided). The compatibility rule is restated: new top-level keys need a major bump unless a run-level `extensions` slot exists in the same release — 2.0.0 adds that slot.
2. **Schema 2.0.0 contents**: top-level `stages` object (run-wide and per-document stage status `not_run|complete|failed|skipped`, every distinct failure reason in recording order, the stage-contract table used for completeness so the artifact is self-interpretable); run-level `extensions` slot; run-level `resumed_documents` (documents of the corpus not processed in this run, with a pointer — path/digest — to the artifact that holds their provenance, when known); a run-instance identity separate from the configuration identity; `ClaimNode.answer` (`asserted|not_reported`) plus the absence-verification state; `PrivacyCarrier.decision_id`; completeness report carrying per-document and run **absence counts** (asserted, supported, unsupported, verified absence, unverified absence). Explicit edges and un-elided records stay (no dropping of `belongs_to_source`/structural edges, no cited-only evidence nodes — both rejected as less self-describing and contrary to Req 4.1/8.3).
3. **Completeness/validation semantics**: (a) `nr` handling — typed `answer`, new overridable info finding `unverified_absence` (nr without checked-evidence ids), verified absence (nr with ids) is `supported`; absence claims are claim-level `complete` and **quantified, not hidden** (counts in the completeness report); a pipeline-synthesised `nr` (merge of empty value, prefill fallback) gets a non-model origin (Req 5.7). The token set classified as `nr` and the synthesised-`nr` marker come from `extraction-contract-hardening`; provenance does not re-interpret. (b) A required stage that was never marked reads `undetermined` when its upstream stages are complete; `mark_stage_skipped(stage, reason)` records an intentional skip. (c) Findings of severity `critical`/`error` attributable to a document, claim or node make that document/claim `incomplete` with a stated reason (`invalid_identifier` attributed through `details["source_id"]`); the validation report and completeness must agree on what each means; the findings-blind statement in the design is removed. (d) `duplicate_identity` consequences for same-content PDFs are stated and tested.
4. **Remove the exhaustion-retain path** from `RepairRetryLoop`/`process_pdf` so provenance on/off are behaviourally identical (extraction acceptance never depends on the observer). A document whose repair is exhausted is a failed document: stage `extraction_chunk`/`synthesis` failed for that source with the reference-only reason carrying the offending ids (use `exc.metadata["last_error"]` for the synthesis reason), document `undetermined`. Req 5.4 is reinterpreted as "provenance retains the claims it is handed and records reference issues naming claim, reference and kind"; the 6.4 observable is reworded (duplicate/ambiguous reference in an accepted output; reference findings from accepted outputs). The 8 pinned tests are re-pointed.
5. **Record the model-visible evidence**: consume the per-call shown set from `extraction-contract-hardening`; an evidence-selection/pruning derivation step per document (inputs all evidence nodes, outputs the shown nodes, removed ids with reason `cap|budget|…`), extraction/synthesis steps whose inputs are the evidence actually in the prompt (claims cite a subset), a finding when a claim cites an evidence node outside that call's shown set (should be unreachable once validation is shown-set based). New stage(s) are declared in both contract tables and in the 7.3 drift-guard inventories.
6. **Durability and scale**: public `ProvenanceRecorder` accessors (`run`, `get_node`/`has_source`) replacing per-document snapshots; streaming `write_graph` (byte-identical output for equal graphs; incremental encoding; `indent=2` kept for human inspection) with the write contract restated (no partial file, no clobbering a previous artifact; failure naming the path) and its five tests re-pointed; **per-document durable shards** written atomically when a document finishes (success or failure) plus a recovery path that assembles the run artifact from shards after a crash/OOM kill; a rerun regenerates or recovers provenance instead of silently skipping resumed documents.
7. **Resumed and empty runs**: resumed documents are listed in `resumed_documents` with a pointer to their earlier artifact; an empty run (every document resumed / no fingerprint) writes an `undetermined` artifact stating why; an artifact never silently overwrites a different run's artifact (run-instance identity in the path or a guard). cost-and-run-reporting's resume gate and `pdf_processor.is_resumed` must stay in sync (Upstream note already added there).
8. **Identity**: include `sanitize_extracted_values`/`exported_value_normalizer` in the config fingerprint (persisting as the documented fingerprint boundary), add a run-instance identity derived from configuration identity + processed document set + `created_at`; state which one audit-export must use for what.
9. **Privacy attach path (W8)**: graph-level `attach_carriers(graph, carriers)` (new graph, idempotent for equal carriers, conflicting replacement is an error, unknown ids ignored with a WARNING, never reads label/decision values), applied by `finish_run_provenance` through an optional `carrier_source` callback before validation and again after `attach_validation` so the ValidationRecord can be covered; `decision_id` on the carrier ties a node to the privacy audit record; absent callback ⇒ byte-identical artifact. Which node kinds get which carrier remains privacy-core's policy decision.

## Interfaces published by `extraction-contract-hardening` (spec generated 2026-10-12; read its `design.md` and `research.md` before designing)
- `ShownEvidence` (stdlib-only leaf module `shown_evidence.py`): the per-call shown set, parsed from the package text actually sent, after budget mitigation; repairs reuse the original call's set; synthesis has its own (ids only in prior context are not citable); `package_ids` for the ids present; exposed on `RepairRetryLoop.shown_evidence`. v2 consumes it; it never re-derives it.
- Validation outcome codes on `ValidationError.codes` (including a distinct `not_shown` reason: the id exists in the evidence map but was not provided in this request's package). Until v2 removes the exhaustion-retain path, retained references are judged against the shown set with `reason: "not_shown"` — v2's removal of that path is therefore an edit of already-hardened code.
- Missing-value contract: exactly `nr` (strip/casefold, canonicalised) ⇔ confidence `nr`; `nr` with ids (all shown) = verified absence, `nr` without ids = unverified absence; empty value accepted only as `c=nr` without ids, normalised and marked. Persisted optional field key `nr_origin ∈ {model, pipeline_empty_value, pipeline_prefill}`, present exactly on `nr` fields; `MergeResult.synthesised_not_reported` carries the merge's synthesised indices. `ClaimOrigin` (`model|prefill|human|import`) has no member for `pipeline_empty_value` — **v2 decides the mapping** (recommendation: `pipeline_prefill` → `prefill`; `pipeline_empty_value` → a new non-model origin, or `import`-like `derived`; the vocabulary change is part of the 2.0.0 release) and records it in the Compatibility rule.
- `EXTRACTION_CONTRACT_VERSION` ("2.0.0"): manifest `complete` entries gain `extraction_contract`. `run_id` excludes `agent_schema.json`, so v2 may include the contract version in the configuration fingerprint (decision 8) — v2 decides and records why.
- Fallback prefill confidence: `h` only for header-sourced values; a fallback year keeps its value with `l`; the paper-id author fallback becomes `nr`/`nr` with `nr_origin = pipeline_prefill`. Header citations in `claim_provenance.header_citations` must stay equivalent (pinned by an equivalence test in the hardening spec).
- Uncited asserted values (c∈h/m/l with empty `loc`) are rejected and repaired in the pipeline; so after both specs an accepted output contains no asserted claim without evidence — provenance's `unsupported` state then arises only from non-model origins, adapter-dropped ids and corrupt caches. v2's completeness tests must reflect that.
- New code uses `call_kind`, not `stage`/`stages` parameters (the 7.3 drift guard); v2's own new stage-taking functions must be registered in the 7.3 inventories.

## Scope
- **In**: everything in decisions 1–9; amendments of `provenance-core` requirements/design where superseded (recorded as a revision, not by rewriting history); CHANGELOG, steering/config/README/CLAUDE.md syncs; tests, including property/guard/e2e updates, schema golden for 2.0.0, and a differential test that provenance on/off produce identical extraction outputs/manifests/model calls.
- **Out**: privacy classification/decision logic (privacy-core); audit-package/export formats (provenance-audit-export); reviewer UI; the extraction contract itself (shown-set computation, `nr` token semantics, prompt text — `extraction-contract-hardening`); fixing cross-invocation resume (cost-and-run-reporting) — this spec only makes provenance honest about it; any tolerance policy for bad evidence ids in the pipeline.

## Boundary Candidates
- Schema/vocabulary (models, serialization) vs completeness semantics vs emission wiring vs durability (shards, streaming) — four seams.
- Provenance observing the pipeline vs the pipeline's own behaviour (the retain-path removal restores the boundary).

## Upstream / Downstream
- **Upstream**: `provenance-core` (implemented, superseded in part), `extraction-contract-hardening` (shown set, `nr` contract, synthesised-`nr` marker — must land first or be developed against its published interfaces).
- **Downstream**: provenance-audit-export (`stage_failures` from `stages`), reviewer-ui, public-private-provenance (event log, carriers), privacy-core (`attach_carriers`, `decision_id`), cost-and-run-reporting (resume gate, `RunProvenance` name collision already noted), evaluation-harness (asserted-only denominator from absence counts).

## Constraints
- Python 3.12.x; dependency rules unchanged (`provenance` imports no pipeline/quality_control/agents/pdf_extractor; the 7.1 import-isolation, hashing and evidence-id construction guards, the 7.2 property tests, the 7.3 prefix goldens and drift guards, the 7.4 e2e test are all updated deliberately, never weakened).
- `_shared_paper_prefix` stability: provenance never touches prompts; the evidence-selection recording must not alter selection.
- Provenance never aborts extraction; every new path degrades with a WARNING; `MemoryError`/OOM must not lose already-written shards.
- Determinism: equal graphs serialise byte-identically (including shards and the streamed artifact).
- No PHI/credentials in fixtures; all new vocabulary members/fields documented in the Compatibility rule.
